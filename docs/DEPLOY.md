# Deploying Eclipso (staging.eclipso.lol)

Server: Hostinger VPS 2.24.48.245 (see docs/VPS.md). eclipso.lol still serves the static Coming soon page; the real
website runs on **https://staging.eclipso.lol**, protected by a browser password (stored on kindmops's PC in
`.local\staging-login.txt`, never in Git).

## Layout on the server
| What | Where |
|---|---|
| Releases (5 kept) | `/opt/eclipso/releases/<date>-<commit>/` (website, frontend, public, admin, libraries, sql, deploy) |
| Active release | `/opt/eclipso/current` → a release; name in `/opt/eclipso/DEPLOYED` |
| Private config | `/etc/eclipso/appsettings.json`, `secrets.json`, `db-password` (generated on the server, root:eclipso 640) |
| Data | PostgreSQL `eclipso` (localhost:5432), uploads `/var/lib/eclipso/{storage,thumbnails,groups}` |
| Cache | Redis 127.0.0.1:6379 (sessions are authoritative in PostgreSQL) |
| Services | `eclipso-website` (.NET, 127.0.0.1:5080), `eclipso-frontend` (Next.js, 127.0.0.1:3000), Caddy (HTTPS) |
| Backups | `/var/backups/eclipso` nightly 04:15, 14 days; also taken before every deploy |

Production settings (generated by `deploy/server/make-config.py`): LocalDevelopment off, `/local` test endpoints off,
Swagger off, untrusted content processing off, Secure cookies on, client IP from Caddy's `X-Eclipso-Client-IP` only.

## Deploy the current commit (from kindmops's PC)
1. Unlock the SSH key once per PC restart: `ssh-add "$env:USERPROFILE\.ssh\eclipso_vps"` (PowerShell).
2. Commit your changes (the script refuses uncommitted code).
3. In the project folder run:

```bash
python local/deploy-staging.py
```

It builds, uploads, backs up the database, applies new migrations, switches release, and health-checks.
**If the new release does not start, it automatically switches back to the previous one.**
4. Verify: `python local/test-staging.py` (should print PASS for every line).

## Roll back by hand
```bash
ssh kindmops@2.24.48.245 "ls -1t /opt/eclipso/releases"
```
then, with the release name you want:
```bash
ssh kindmops@2.24.48.245 "sudo ln -sfn /opt/eclipso/releases/RELEASE /opt/eclipso/current && sudo systemctl restart eclipso-website eclipso-frontend"
```
Database migrations are additive (new tables/columns/constraints), so an older release runs against the newer schema.
If a future migration is not additive, its file must say so and include restore instructions.

## Restore the database from a backup
Tested 2026-10-28: a backup restored into a scratch database matched the live one exactly.
```bash
ssh kindmops@2.24.48.245 "sudo sh -c 'ls -1t /var/backups/eclipso'"
```
Full restore (replaces live data with that backup — stop the website first):
```bash
ssh kindmops@2.24.48.245 "sudo systemctl stop eclipso-website && sudo -u postgres dropdb eclipso && sudo -u postgres createdb -O eclipso eclipso && sudo -u postgres pg_restore -d eclipso /var/backups/eclipso/db-STAMP.dump && sudo systemctl start eclipso-website"
```
Uploaded files: `sudo tar -xzf /var/backups/eclipso/files-STAMP.tgz -C /var/lib/eclipso`.

## Make an account the site owner on staging
```bash
ssh kindmops@2.24.48.245 "sudo python3 /opt/eclipso/current/deploy/make-config.py --release /opt/eclipso/current --site https://staging.eclipso.lol --owner-user-id ID && sudo systemctl restart eclipso-website"
```
